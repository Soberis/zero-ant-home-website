# Repository Guidelines

## Project Structure & Module Organization
This is a Vue 3 + TypeScript marketing site built with Vite. Under `src/`, `views/` holds pages, `components/` shared UI, `router/` routes, `locales/` translations, `composables/` shared logic, `data/` content modules and image manifests, and `utils/`/`types/` utility code. Static assets live in `public/`. Build output goes to `dist/`. Deployment templates live in `config/`, and helper scripts live in `scripts/`.

## Build Pipeline Order (Critical)
The build pipeline has three sequential phases — never run `vite` directly:
1. **Pre-build**: `scripts/generate-responsive-images.mjs` generates WebP/AVIF variants to `public/responsive/` and writes the manifest to `src/data/responsive-images.generated.json`.
2. **Vite build**: produces `dist/index.html` and bundled assets.
3. **Post-build (SSG)**: `scripts/generate-site-artifacts.mjs` reads the built `index.html`, locale JSON, data modules, and the responsive manifest, then generates per-route HTML files with SEO metadata + `sitemap.xml`.

Commands:
- `yarn dev` — runs step 1, then starts Vite dev server.
- `yarn build` — runs all three steps.
- `yarn preview` — serves the built `dist/`.

## Generated/do-not-edit directories
- `public/responsive/` — gitignored, generated by the responsive image script. Do not create or edit files here.
- `dist/` — entire build output, never edit directly.
- `src/data/responsive-images.generated.json` — auto-generated manifest consumed by the SSG step.

## Environment Variables
- `VITE_SITE_URL` — site base URL, defaults to `https://zeroant.com`.
- `VITE_BAIDU_ANALYTICS_ID` — Baidu analytics site ID; analytics script only loads when this is set.
- `ANALYZE` — set to enable bundle visualizer output (`yarn build:analyze` sets this automatically).

## Package Manager
Use `yarn` only (pinned to Yarn 1, `packageManager: yarn@1.22.22`). Node `>=20.16.0`.

## Lint, TypeCheck, Test Commands
- `yarn lint` / `yarn lint:fix` — ESLint (flat config at `eslint.config.js`).
- `yarn type-check` — `vue-tsc --noEmit`. Note: `noUnusedLocals: true`, `noUnusedParameters: true`, and `exactOptionalPropertyTypes: true` in tsconfig.
- `yarn test:node` — Node-side Vitest (routing, i18n, SSG artifacts). Test files live in `tests/node/**/*.test.ts`.
- `yarn smoke` — post-build smoke check that verifies the built `dist/` for correct SEO, responsive assets, service worker policy, nginx rules, etc. Must run AFTER `yarn build`.
- `yarn validate` — full gate: `lint → type-check → build → smoke` (in that order).

## Routing & Locale
- Routes are defined in `src/router/routes.ts`. Every route path is wrapped with `getLocalizedRoutePath()` which produces `/:locale?/path`.
- Default locale is `zh` (no prefix, e.g. `/products`). English uses `/en` prefix (e.g. `/en/products`).
- `src/router/routes.ts:77-84` — legacy routes `/system-products/*` and `/robot-products/*` redirect to `/products`.
- Catch-all 404 route is defined last.

## i18n Blocking Mount
`src/main.ts:34` — `initI18n()` loads locale messages asynchronously, and `app.mount("#app")` only runs after it resolves. This ensures the first render has translations ready. If locale messages fail to load, the app still mounts to avoid a white screen.

## Font Loading Strategy
Critical weights block rendering: Geist Sans 400/500 (body/nav) and Outfit 600 (hero headings). Non-critical weights (Geist 600/700, Outfit 400/500/700) are dynamically imported after mount via `setTimeout(loadDeferredFonts, 0)`.

## Responsive Image System
- Source images are referenced in `src/data/responsive-image-sources.json` (products, videos, showcase), `src/data/product-center.ts` (products), and `src/data/videos.ts` (videos).
- Adding a new image: update the source map AND the usage in data files. The responsive image script validates cross-references and fails on missing entries.
- Images are generated in both WebP and AVIF at multiple widths.
- The Vite image optimizer plugin (`vite.config.ts:32-36`) explicitly excludes `/responsive/` because those files are already pre-optimized.

## SEO Architecture
Two layers:
1. **Runtime SEO** (`src/main.ts:92-167`): An `afterEach` router guard dynamically sets `<title>`, meta tags, and structured data based on route name via `src/router/seo.ts`.
2. **Static SEO** (`scripts/generate-site-artifacts.mjs`): Post-build, every route × locale combo gets a pre-rendered `index.html` in `dist/` with full SEO metadata, Open Graph tags, Twitter cards, alternate hreflang links, and JSON-LD structured data. A `sitemap.xml` is also generated.

## Nginx / Deployment
- Nginx config is templated from `config/nginx.conf.template` — edit this file, not server config.
- **No SPA fallback**: Nginx is configured with `try_files $uri $uri/ =404;`, meaning unknown routes return 404. Every valid route must have a pre-rendered `index.html` or the SSG step must cover it.
- `develop` branch deploys to test server; `main` branch with version tag (e.g. `v1.0.0`) deploys to production.

## Coding Style
- Prettier config: 2-space indent, double quotes, semicolons, `es5` trailing commas, 100-column wrap, `vueIndentScriptAndStyle: false`.
- ESLint: `vue/multi-word-component-names` is off. `@typescript-eslint/no-unused-vars` is `warn` with underscore-prefix ignore.
- PascalCase for Vue components, camelCase for utilities/composables, kebab-case for route-facing files.
- Import alias: `@` → `src/`.
- `unplugin-vue-components` auto-generates `components.d.ts` — this file is gitignored.

## Testing Guidelines
Tests live under `tests/node`. Name new files `*.test.ts`. No coverage threshold. Focus on routing, i18n, formatting, and SSG artifact correctness.
