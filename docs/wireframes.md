# ZeroAnt 低保真页面草图 V4

> 目的：把 `design-plan.md` 的最新结构落成可执行线框，先统一页面骨架、信息顺序、Bar 体系和公共区块，再进入视觉细化。  
> 说明：这是低保真草图，规定的是布局关系和信息优先级，不代表最终视觉。  
> 对应方案见 [design-plan.md](./design-plan.md)。

## 0. 当前适用范围

这版草图按新的交付边界组织：

1. 产品中心
2. 产品详情页
3. 公共区块联动：`NavBar`、`Footer`、`Sticky Filter Bar`、`Sticky Anchor Bar`

首页仍然保留在文档里，但只作为“中下段收敛参考”，**不是本轮重做 Hero 的依据**。

补充口径：

- 前台只保留单一 `/products` 入口。
- 文档方案中不再保留任何历史产品路由或兼容跳转口径。
- 产品中心本轮展示项以 `src/assets/images/product` 目录中的确认图片为准，`封面.png` 只作封面资源。
- 页面里的参数字段和差异说明，统一参考 `参数/产品-横版草稿7(1).pptx` 与 `参数` 目录下的参数图。
- 头部、首页、Footer 统一只保留“产品中心”一个产品入口命名。

### 2.2 结构说明

- 页面组织方式参考睿尔曼产品中心，核心是 `系列导航 -> 系列区块 -> 型号卡片 -> 扩展机构专区`。  
  来源：[睿尔曼产品中心](https://www.realman-robotics.cn/products)
- 顶部 Hero 只负责说明“这里是什么”，不做复杂叙事。
- 每个系列都先给一句系列说明，再进入型号卡片。
- `ZA-R3 / ZA-R3X` 这组卡片必须直接写出“臂长差异”。
- `ZA-R3L / ZA-R3M / ZA-R3H` 这组卡片必须直接写出“立柱高度 / Z 轴行程差异”。
- 扩展机构必须单独分块，不能和主机型号混排。
- Sticky Filter Bar 是本页一级导航，不要做成花哨 tabs。
- 页面默认展示项以 `src/assets/images/product` 目录为准，不再混入旧占位型号。

### 3.2 详情页结构说明

- Hero 必须与当前型号绑定，不能只是泛产品图。
- 型号切换放在 Hero 下方，属于一级交互。
- 参数展示拆成两层：
  - 快速看：核心参数卡片
  - 深入比：完整对比表
- `ZA-R3 / ZA-R3X` 的详情页必须直接体现臂长差异。
- `ZA-R3L / ZA-R3M / ZA-R3H` 的详情页必须直接体现立柱高度 / Z 轴行程差异。
- 关联扩展机构和推荐组合属于业务闭环，必须紧跟参数区之后。
- Sticky Anchor Bar 要和产品中心的 Filter Bar 使用同一体系的视觉规则。

│ 产品中心        支持与下载        行业应用          联系方式 / 二维码        │

- Footer 不是信息垃圾桶，只保留和现有结构强相关的入口。
- 头部和底部不能讲两套分类语言。
- Footer 只保留“产品中心”与 `/products` 这一种产品入口表达。

### 4.3 Bar 体系

```text
产品中心：
[全部] [R系列] [M系列] [MR系列] [具身平台] [控制器] [扩展机构]

产品详情页：
[概览] [参数对比] [关联扩展] [推荐组合] [案例] [下载]
```

- `Filter Bar` 负责跨 section 切换。
- `Anchor Bar` 负责详情页内部跳转。
- 两者视觉上属于同一体系，只允许信息层级不同，不允许样式像两套系统。

## 5. 草图使用原则

- 先用这些草图对齐结构，再进入视觉细化。
- 如果页面内容增加，先检查能不能放进既有结构，不行再改结构。
- 首页 Hero 本轮不重绘，不要拿线框文档反推首屏重做。
- `NavBar`、`Footer`、`Sticky Bars` 视为本轮联动范围，不允许最后再补。

## 6. 下一步建议

建议按这个顺序推进：

1. 先做 `NavBar / Footer / ProductsLayout` 的公共骨架
2. 再做产品中心页面骨架，挂载到现有 `RobotProducts.vue`
3. 最后做 `ProductDetail.vue`
